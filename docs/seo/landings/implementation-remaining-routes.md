# Оставшиеся пять маршрутных лендингов

Реализованы локально, без публикации. Теперь у всех 15 пар из `tariffs.heavyCargoPrices[0].price` есть отдельная страница.

## Страницы и подтверждённые условия

| Страница | Пара | Расписание | Контакты отправки / получения |
|---|---|---|---|
| `vladivostok-komsomolsk-na-amure.html` | vvo → kms | Еженедельно | Евгений / Наталья в Комсомольске-на-Амуре |
| `ussuriysk-komsomolsk-na-amure.html` | uss → kms | Дата согласовывается | Терминал Уссурийска / Наталья в Комсомольске-на-Амуре |
| `ussuriysk-blagoveshchensk.html` | uss → blg | Дата согласовывается | Терминал Уссурийска / Наталья в Благовещенске |
| `blagoveshchensk-komsomolsk-na-amure.html` | blg → kms | Дата согласовывается | Наталья в Благовещенске / Наталья в Комсомольске-на-Амуре |
| `komsomolsk-na-amure-vladivostok.html` | kms → vvo | Еженедельно | Наталья в Комсомольске-на-Амуре / Яна |

Сроки для этих пар в `business-data.pug` не подтверждены: они не заимствуются у других направлений, посетителю предлагается согласовать срок до передачи груза. Часы приёма и подачи заявки не выдаются за расписание рейсов. Упаковка как услуга предлагается только при отправлении из Владивостока; для остальных городов приведена инструкция о подготовке груза.

## Дизайн-план и результат

Основа — `docs/route-landing-design.md` и навык `frontend-design`.

- PT Sans; белый `#ffffff` и подложка `#f2f7fa`, графитовый текст `#243746`, ссылки `#00658c`, синий иллюстраций `#0098cc`, маршрутный оранжевый `#ff8800`. Все цвета через существующие токены, обе темы без отдельной палитры для каждой страницы.
- Сетка 1080 px: слева города, пояснение и действия, справа иллюстрация и факты. На телефоне иллюстрация скрывается, факты предшествуют действиям.
- Один сюжет на направление, без конкурирующих декоративных карточек. Индивидуальные акценты основаны на подтверждённом расписании, передаче груза, принципе расчёта, географии городов и получении груза; не на выдуманных преимуществах.

| Направление | Первый экран | Документы / мелкий / тяжёлый / объёмный груз |
|---|---|---|
| vvo → kms | Недельный лист отправки без выдуманного дня недели | Открытая брошюра / бутылка в защитном вкладыше / электродвигатель / табурет |
| uss → kms | Схема передачи между двумя терминалами | Рулон бумаг / свёрток для инструментов / металлические гири / вентиляционное колено |
| uss → blg | Вес и объём как два параметра расчёта | Прозрачный пакет / защищённый телефон / цепь в поддоне / лёгкая чаша |
| blg → kms | Два города на Амуре, схема направления | Фолио с карточками / мягкий почтовый пакет / тиски / стеллаж |
| kms → vvo | Груз у зоны получения | Альбомный отчёт / шестигранный контейнер / чугунный радиатор / защищённое велосипедное колесо |

Все 25 SVG созданы для проекта; сторонние изображения и лицензии не добавлены. Схемы не являются картами фактического пути, изображения терминалов — не их архитектурные портреты. Иконки иллюстрируют категории, а не размеры конкретного отправления.

Для основной иллюстрации используется существующий `initRouteSceneAnimation`: однократная прорисовка связи и появление груза, без циклов. Сохранены статичный SVG без JS, отключение движения по настройке пользователя и проверка видимости мобильной иллюстрации.

Общая структура пяти новых страниц вынесена в `src/pug/route-shipment-content.pug`; каждая страница задаёт пару, подтверждённые контакты, самостоятельные тексты, FAQ, иллюстрацию и связанную страницу. Общие компоненты существующих лендингов не переписывались. Иконки подключает `src/pug/shipment-cargo-icons.pug` через `routeExamples`.

## Расчёты и интеграция

Примеры считает `calculateCargo`, таблицы используют `tariffs.pug`. Контрольные суммы в рублях, по порядку документов / мелкого / тяжёлого / объёмного груза:

| Пара | 0,3 кг / 0,001 м³ | 10 кг / 0,1 м³ | 500 кг / 1 м³ | 100 кг / 1 м³ |
|---|---:|---:|---:|---:|
| vvo → kms | 350 | 850 | 8 500 | 3 400 |
| uss → kms | 350 | 800 | 7 750 | 3 100 |
| uss → blg | 350 | 850 | 8 250 | 3 300 |
| blg → kms | 250 | 700 | 7 000 | 2 800 |
| kms → vvo | 200 | 400 | 4 000 | 1 600 |

Указаны НДС, границы обычного груза, исключённые надбавки и отдельная оплата дополнительных услуг. Условия хранения и время подачи заявки берутся из общих данных.

Добавлены пары в `src/js/common/route.js`, ссылки с главной и прайса, ссылки между подходящими маршрутами. Self-canonical и sitemap собираются стандартно. Частота рейсов на главной сохранена только для шести подтверждённых пар; остальные девять находятся в отдельной группе без выдуманного расписания.

## Проверка

- `npm run build` — успешно. Первый запуск прервался при проверке canonical существующей страницы; повторный и итоговый полные запуски успешны, исходник её canonical не менялся.
- `npm test` — 156 тестов успешно, включая 21 новый тест в `tests/remaining-route-landings.test.js`.
- `npm run lint`, `git diff --check` — успешно.
- Тесты проверяют заголовки, метаданные, пары, расписание, все 55 тарифных ставок, 20 примеров, адреса, роли телефонов, услуги, ссылки, аналитику и наличие всех 15 тарифных пар среди страниц. Проверяется различие геометрии новых SVG от существующих; визуальная оценка дополняет эту проверку.
- Chrome: все пять страниц на 320, 768 и 1280 px в светлой и тёмной темах с раскрытыми таблицами — без горизонтального переполнения страницы. На 320 × 600 px с размером текста 200% переполнения нет; навигация становится статичной. Первый экран просмотрен на скриншотах.
- В изолированном браузерном контексте проверено предзаполнение всех пяти пар в калькуляторе и заявке. При сохранённой паре vvo → khb и ссылке uss → blg города не перезаписываются, появляется предупреждение.
- Контент, нативные раскрытия, ссылки и скрытые дополнительные кнопки без JS проверены по сгенерированному HTML. Отдельный браузерный прогон с полностью отключённым JavaScript не проводился.

Отправка заявки через PHP, доставка писем, внешняя приёмка целей Метрики и публикация не выполнялись. Имеющиеся до начала задачи изменения по Благовещенск → Владивосток сохранены.
