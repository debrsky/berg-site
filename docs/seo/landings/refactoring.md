# Рефакторинг маршрутных лендингов

## Граница изменения

Все 15 лендингов переведены на общие компоненты без редизайна и редакционных изменений. Сохранены URL, метаданные, тексты, тарифы, контакты, геометрия иллюстраций, порядок секций и поведение действий. Текущие незакоммиченные изменения сохранены; публикация не выполнялась.

Дизайн-план: существующие PT Sans, токены цветов, сетка и мобильные правила остаются неизменными. Индивидуальность страниц сохраняется через тексты, SVG и слоты компонентов, а не через ветвления по идентификатору конкретного направления. CSS-бандл лендинга побайтово совпадает с эталоном до рефакторинга.

## Архитектура

- `src/data/route-landings.js` — единственный реестр пар, slug, основных иллюстраций, наборов грузовых иконок и связанных направлений. Связи задаются стабильными идентификаторами пар. Реестр используется навигацией главной, ссылками прайса и аналитикой; тарифы и подтверждённые расписания в него не перенесены.
- `src/pug/business-data.pug` — у телефонов появились стабильные `id`, у терминалов — явные назначения `contacts.sending`, `contacts.receiving`, `contacts.general` и ссылки проезда. Время приёма и заявки хранится отдельно; из тех же значений формируются полные правила и пояснения лендингов.
- `gulp/landing-data.js` — подготовка контекста страницы и SVG. Неизвестные/нетарифицированные пары, отсутствующие и неоднозначные контакты, дубли реестра, сломанные связанные ссылки, отсутствующие SVG и недопустимая SVG-разметка не заменяются случайными значениями, а вызывают ошибку.
- `src/pug/landing-layout.pug` — получает `landingId` и централизованно назначает путь и контакты. Автор страницы задаёт метаданные и композицию.
- `src/pug/route/` — секции первого экрана, стоимости, операций, терминалов, вопросов и финальных действий. Факты, шаги, услуги и FAQ допускают индивидуальное содержимое через блоки. Хабаровск → Владивосток сохраняет раздельные приём и получение; Владивосток → Благовещенск — секцию планирования и действие «Согласовать отправку»; последние пять страниц явно задают порядок секций вместо одного общего монолитного шаблона.
- `src/pug/route-components.pug` — действия, телефон, таблицы и четыре рассчитываемых примера; длинные цепочки выбора SVG удалены.
- `src/data/landing-copy.js` — общие формулировки тарифных условий, без повторения в каждой странице.

SVG остаются inline: общие CSS-токены и существующие обработчики анимации продолжают работать. В браузер попадает только рисунок текущего направления, не полный каталог SVG. Четыре исходные Pug-иконки эталона сохранены отдельными файлами в `src/img/cargo-examples/standard/` без изменения геометрии.

## Сборка и watch

`gulp/pages.js` использует ту же задачу, что `gulp/pug2html.js`: одинаковые locals и валидация при полной сборке, изменении страницы и изменении общего шаблона. Поток рендера ожидается через `pipeline`, ошибки не маскируются успешным завершением задачи.

При изменении `src/data/**/*.js` пересобираются HTML и JS. Данные перечитываются с учётом mtime, SVG — заново для каждого запуска рендера: модульный кеш не должен сохранять старые тексты/иллюстрации в watch. Отдельный длительный интерактивный прогон watch не выполнялся; проверена общая задача сборки.

## Тесты

- `tests/landing-contract.test.js` — параметризованные проверки всех 15 страниц: ссылки и якоря, предзаполнение, аналитика, ресурсы, скрытые дополнительные элементы и доступность нативной разметки без JS.
- `tests/fixtures/route-landings.sha256.json` — 15 независимых контрольных хешей HTML, взятых **до** рефакторинга, не из нового реестра. Игнорируются комментарии и форматирование между тегами; структура, текст, атрибуты, метаданные и геометрия SVG сохраняются.
- `tests/landing-data.test.js` — полнота реестра по тарифным парам, независимые ожидаемые телефоны, выбор контактов после перестановки массива/изменения роли, отсутствие fallback, расписание, время, SVG и отказ при ошибочных данных.
- Повторяющиеся циклы проверки ссылок в маршрутных тестах заменены общим контрактом; отдельные проверки цен, телефонов, расписания, услуг, количества CTA и рисунков сохранены.
- `tests/helpers/landing-data.js` — единая загрузка фактических тарифов/условий для тестов. Ожидаемые цены, номера и хеши не генерируются из проверяемого реестра.

При намеренном будущем изменении HTML сначала проверить тексты и результат в браузере, затем осознанно обновить соответствующий хеш. Не перегенерировать все ожидаемые значения только ради зелёных тестов.

## Результаты проверки

- `npm run build` — успешно.
- `npm test` — **195 тестов успешно**.
- `npm run lint`, `git diff --check` — успешно.
- Все 15 HTML совпадают с предрефакторинговым эталоном после исключения комментариев и форматирования между тегами; CSS совпадает побайтово.
- Для трёх различных компоновок (Владивосток → Хабаровск, Хабаровск → Владивосток, Владивосток → Комсомольск-на-Амуре) сделаны полностраничные скриншоты до/после на 320 и 1280 px в обеих темах. Все **12 пар PNG побайтово совпали**. Для детерминированного сравнения декоративная анимация была отключена настройкой уменьшения движения, шрифты загружены.
- Все 15 страниц проверены в Chrome на 320, 768 и 1280 px в обеих темах с раскрытыми таблицами: 90 проверок без горизонтального переполнения. Дополнительно проверено окно 320 × 600 px с текстом 200%: навигация статична, переполнения нет.
- На Уссурийск → Благовещенск клавиша Enter раскрывает тарифы, нижняя кнопка закрывает их с возвратом фокуса; якорь терминалов не перекрыт меню, текущий раздел отмечен.

Pug страниц и общих маршрутных компонентов стало примерно на треть меньше (до: 2396 строк; после: около 1650). Это показатель устранения дублирования шаблонов, а не обещание ускорения загрузки: появились явный реестр, загрузчик и дополнительные проверки.

## Ограничения

Отправка заявок через PHP, внешняя приёмка Метрики и публикация не выполнялись. Отдельный браузерный прогон с полностью отключённым JS не проводился: доступность статического содержимого проверена по HTML и неизменности разметки. Существующие спорные редакционные формулировки не исправлялись под видом рефакторинга; в частности, узкое пояснение про заявку на машину у эталона требует отдельного редакционного изменения.
