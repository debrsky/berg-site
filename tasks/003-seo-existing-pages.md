## Контекст

Общий H1 находится в `src/pug/header.pug`; названия страниц обычно H2. Главная содержит преимущественно слайдер, общий description повторяется на разных страницах. Canonical задан непоследовательно. robots.txt доступен на сервере, но не воспроизводится исходниками.

## Цель

Сделать существующие индексируемые страницы самостоятельными содержательными ответами с корректными заголовками, метаданными и воспроизводимой конфигурацией индексации.

## Входит в задачу

Тематические H1 и метаданные; содержательные блоки главной; применение справочника SEO-02; абсолютные canonical; robots.txt в исходниках; валидация SITE_URL для sitemap; микроразметка организации/филиалов по утверждённым данным; размеры изображений и lazy loading непервых слайдов; регрессионные SEO-проверки.

## Не входит в задачу

Маршрутные лендинги, новый движок/фреймворк, изменение тарифной логики, полная переделка дизайна, редиректы и очистка сервера из SEO-01, публикация без отдельного разрешения.

## Текущее поведение

`src/pug/layout.pug` задаёт общие метаданные и шапку. `gulp/sitemap.js` строит карту из HTML без проверки SITE_URL. `gulp/copy.js` умеет копировать `src/*.txt`. Служебные страницы используют noindex. HTML главной доступен без JS, фотографии имеют AVIF/WebP.

## Ожидаемое поведение

На каждой индексируемой странице свой видимый H1, содержательные title/description и один абсолютный self-canonical. Главная раскрывает услуги и географию. Контакты и расписания берутся из согласованных данных, цены не копируются вручную. robots.txt и sitemap воспроизводятся сборкой без включения клиентских документов и служебных страниц.

## Критерии приёмки

- [x] Все индексируемые HTML имеют ровно один тематический видимый H1; логотип не H1, иерархия подзаголовков сохранена.
- [x] Title и description уникальны среди индексируемых страниц; содержат только подтверждённые условия, а не перечни ключевых слов.
- [x] Главная содержит услуги, географию, условия отправки, подтверждённые преимущества и ссылки на прайс, калькулятор, заявку и контакты.
- [x] На индексируемых страницах один абсолютный canonical с утверждённым production origin; служебный noindex сохранён.
- [x] Чистая сборка создаёт robots.txt и sitemap; карта содержит только канонические индексируемые HTML с корректными абсолютными URL; некорректный SITE_URL отклоняется явно.
- [x] JSON-LD синтаксически и структурно проверен локально (внешний валидатор не запускался) и не содержит выдуманных филиалов, часов, рейтингов, индексов или услуг.
- [x] У контентных изображений зарезервированы пропорции; главное изображение не lazy, непервые слайды могут загружаться отложенно.
- [x] На ширинах 360 и 1280 px основной контент и навигация доступны; калькулятор и интерфейс заявки проверены локально; реальная PHP-отправка не проверялась.
- [x] `npm run build`, `npm test` и `npm run lint` проверены; исходные/недоступные ошибки отдельно описаны, а не объявлены успешной проверкой.

## Технические ограничения и решения

Pug → HTML, Less → CSS, существующий Gulp; редактируем src, не public. Production canonical — https://bergvl.ru с сохранением /home.html как текущей главной; смена URL главной не входит. Служебные client-doc, controls, order-ok и index не превращаем в посадочные. Не открывать доступ к персональным документам ради индексации; robots/noindex не являются авторизацией. Не обещать расширенный сниппет из-за JSON-LD. Окончательные правила для client-doc проверить с учётом безопасности и текущего запрета обхода.

3. Добавить содержательные блоки главной и улучшить загрузку фотографий.
4. Унифицировать canonical, технические файлы и JSON-LD.
5. Добавить проверки собранных страниц, выполнить команды и ручную регрессию.
6. Подготовить перечень изменений к согласованию и отдельному выпуску.

## Проверка

`npm run build`; `npm test`; `npm run lint`. SEO-тесты запускаются после сборки, поскольку анализируют public. Ручная проверка главной, прайса, контактов, калькулятора, заявки, тёмной/светлой темы и страницы подтверждения на 360/1280 px. Проверить расчёт для трёх выбранных маршрутов; отправку заявки проверять только на настроенном PHP-тестовом сервере. Сравнить HTML с данными SEO-02, JSON-LD проверить валидатором. После разрешённой публикации — HTTP-проверка robots, sitemap и canonical.

## Риски и крайние случаи

Замена H1 не должна менять вид логотипа. Общие блоки не нужно скрывать ради произвольного процента дублирования. При смене условий обновляется справочник, а не несколько независимых текстов. Недоступность PHP/внешних сервисов явно ограничивает приёмку.

## Зависимости и блокеры

Утверждённый SEO-02. Карта SEO-01 нужна для согласования production-редиректов, но локальные правки независимы. Публикация требует отдельного разрешения.
