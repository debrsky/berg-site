## Контекст

На действующем сайте отвечают 200 страницы, которых нет в текущей сборке: `/truck-service.html`, `/pricing20240701.html`, `/pricing-20240201.html`, `/pricing20221001.html`. Вебмастер показывает дубли title у архивных прайсов. Клиентский архив пользователю не нужен.

## Цель

Получить проверенный реестр опубликованных HTML и карту действий для всех устаревших URL; исключить повторное накопление неизвестных страниц без опасного удаления серверных файлов.

## Входит в задачу

Инвентаризация HTML на хостинге; сравнение с чистой сборкой; проверка известных URL и адресов из Вебмастера, sitemap и ссылок; карта редиректов/удалений; проект контроля остатков при публикации. Результаты сохраняются в новых документах ниже.

## Не входит в задачу

Удаление файлов на сервере, публикация, автоматическая синхронизация с удалением, изменение PHP API, скачивание клиентских документов или чтение секретов. Применение согласованной карты выполняется отдельным явно разрешённым выпуском.

## Текущее поведение

`gulp/deploy-z.js` отправляет изменённые файлы, остатки серверного списка выводит в лог. `src/php/deploy/deploy.php` копирует файлы из архива, но не удаляет остаточные публичные файлы. Архив содержит только изменения: отсутствие файла в нём не означает устаревание.

## Ожидаемое поведение

Для каждого публичного HTML известны источник, текущий код, актуальность и решение. Старые прайсы получают план прямого 301 на `https://bergvl.ru/pricing.html`. Для пустого автосервиса без равнозначной замены рекомендуется 410; массовых редиректов на главную нет. Неизвестные страницы не считаются устаревшими автоматически.

## Критерии приёмки

- [x] Для публичных проверенных URL записаны HTTP-код/Location, title, robots/canonical, принадлежность сборке, проблема и действие; для защищённых/служебных URL явно указано исключение из HTTP-проверки по соображениям безопасности.
- [x] Все архивные прайсы из реестра направлены в карте прямым 301 на актуальный прайс; целевая страница отвечает 200.
- [x] Для автосервиса отдельно зафиксировано отсутствие равнозначной замены и решение 410.
- [x] Подготовлен перечень защищённых серверных каталогов и файлов; автоматическое удаление не предлагается.

## Технические ограничения и решения

Сначала read-only аудит. Нужен полный список путей файлов из document root от администратора или через отдельно согласованный read-only доступ; секреты и содержимое приватных файлов не запрашиваются. Клиентское решение: архив прайсов не сохраняем публичным. Предложение автора: прямые 301 для прайсов, 410 для закрытой услуги без замены. Конкретный механизм серверных редиректов определяется после изучения конфигурации; корневой .htaccess в репозитории отсутствует.

## План реализации

1. Выполнить чистую сборку и составить список её HTML.
2. Получить список HTML хостинга и объединить его с известными URL и доступными отчётами Вебмастера.
3. Проверить каждый адрес и заполнить реестр; отделить устаревшее от серверного и служебного.
4. Составить карту действий и проект безопасного контроля остаточных страниц при публикации.
5. Подготовить инструкции резервирования, применения, HTTP-проверок и отката для отдельного выпуска.

## Проверка

`npm run build`; сравнение списков HTML; read-only HTTP GET известных адресов с отключённым автоматическим следованием редиректам. Проверить полноту реестра по серверному списку. После отдельного разрешённого выпуска: старые прайсы возвращают один 301 на актуальную страницу; удалённая услуга — согласованный статус; актуальные страницы, файлы и PHP API сохранены.

## Риски и крайние случаи

Перечень из поисковой выдачи не гарантирует полноту. Возможны старые файлы во вложенных каталогах и серверные маршруты без физического HTML. Полнота реестра ограничивается предоставленным доступом и должна быть явно отмечена. `missing_files` инкрементального деплоя включает в том числе актуальные неизменённые файлы.

## Зависимости и блокеры

Для полного реестра необходим список HTML хостинга/согласованный read-only доступ. Для применения карты позднее необходимы серверная конфигурация, резервная копия и отдельное разрешение на публикацию. При недоступности отчётов Вебмастера фиксировать ограничение, не выдавать аудит за полный.
