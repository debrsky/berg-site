# Инструкции для агентов: bergvl.ru

## Контекст

Это многостраничный сайт транспортной компании «Берг» (грузоперевозки по Дальнему Востоку). Обзор функциональности и структуры — в `README.md`. Основной язык контента и интерфейса — русский.

## Где вносить изменения

- `src/pages/*.pug` — страницы; `src/pug/*.pug` — общие шаблоны (в частности, `layout.pug`, шапка и навигация).
- `src/pug/tariffs.pug` — тарифы, коды городов и адреса; `src/js/common/calculate.js` — общий алгоритм расчёта для калькулятора и примеров лендингов; `src/js/calculator.js` — интерфейс калькулятора. В `src/pages/calculator.pug` находятся форма и JSON тарифов, не алгоритм расчёта. При изменении тарифов проверяйте прайс, калькулятор и примеры лендингов.
- `src/pug/business-data.pug` — независимые расписания и сроки маршрутов, контакты и общие условия; `src/data/route-landings.js` — реестр направлений, URL, иллюстраций и связанных страниц. Контекст лендингов готовит `gulp/landing-data.js`; общие секции — `src/pug/route/` и `route-components.pug`.
- `src/less/` и `src/css/` — стили; `src/js/` — клиентский JavaScript. Точки входа сборки JS: файлы непосредственно в `src/js/*.js`.
- `src/php/` — PHP для отправки заявок, API документов и публикации; `src/files/` — скачиваемые документы; `tests/` — тесты.
- `gulpfile.js` и `gulp/` — задачи сборки и публикации. `public/` — генерируемый результат сборки, игнорируемый Git: редактируйте исходники в `src/`, а не файлы в `public/`.

## Команды проверки

```sh
npm ci
npm run build
npm test
npm run lint
npm run dev
```

Для sitemap при сборке нужен `SITE_URL=https://bergvl.ru` (в Bash: `SITE_URL=https://bergvl.ru npm run build`). Тесты анализируют `public/`: сначала выполняйте сборку, затем `npm test`.

`npm run dev` запускает BrowserSync и отслеживает изменения. Статический локальный сервер не исполняет PHP: для проверки отправки заявок и API документов необходим отдельный настроенный PHP-сервер. Проверяйте затронутые страницы после сборки; для изменений PHP отдельно проверяйте синтаксис (`php -l <файл>`, если PHP установлен). Если какая-либо проверка недоступна или падает, сообщайте об этом, не выдавая её за пройденную.

## Важные связи и ограничения

- Сборка: Pug → HTML, Less → CSS, Rollup → браузерные JS-бандлы, результат — `public/`. Общий шаблон находится в `src/pug/layout.pug`.
- Актуальные решения владельца — в начале `docs/seo/business-data.md`; прежние отчёты и прототипы описывают исторические состояния. Расписания прямой и обратной пары не обязаны совпадать. Комсомольск-на-Амуре полностью исключён из обслуживания; не восстанавливайте его по архивным материалам. PDF/XLSX прайса после закрытия направления пока не обновлялись: это отдельная задача. PHP-обработчик заявки при закрытии направления по указанию владельца не менялся.
- При снятии страницы сверяйте реестр, общие данные, внутренние ссылки, sitemap, точные правила в `src/.htaccess` и тесты. Удаление исходника не удаляет старый HTML с сервера; локальные проверки правил 410 не доказывают их исполнение на production.
- `tests/fixtures/route-landings.sha256.json` проверяет HTML действующих лендингов: обновляйте отдельный хеш только после проверки намеренных изменений, не перегенерируйте все эталоны ради прохождения тестов.
- Форма заявки (`src/pages/order.pug`, `src/js/order.js`) отправляет данные в `src/php/mailer/send.php`. При изменении полей сверяйте генерацию JSON, валидацию и серверную обработку.
- Страница `client-doc.html` (`src/js/client-doc.js`) получает данные из `src/php/api/v0/get_invoice.php` и формирует счёт/УПД. Для API требуются серверные файлы `app/signature.php` и `app/get_invoice.php`, которых нет в этом репозитории. Тесты `tests/upd.test.js` проверяют HTML генератора УПД по хешам: обновляйте ожидаемые значения только после осознанной проверки результата.
- Подсказки и определение города используют DaData; карты и аналитика — сервисы Яндекса. При отсутствии сети эти интеграции нельзя полноценно проверить локально.
- Не раскрывайте содержимое `.env`, `src/php/mailer/config.php` и другие ключи или токены в ответах, логах и коммитах. Для примеров настроек используйте шаблоны. Не запускайте задачи `deploy:dev`, `deploy:prod` или иные задачи публикации без явного запроса пользователя.
- Не изменяйте сторонние библиотеки в `src/vendor/` и `src/php/mailer/phpmailer/`, если задача не требует обновления зависимости.
